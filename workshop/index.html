02 / Your first repository

The first-time workflow

A repository is your project plus its history. Run these steps in your project folder. Replace anything inside <angle brackets> with your own value.

01

Configure your identity first time only

Git records this name and email on your commits.

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
02

Start tracking the folder

Open a terminal inside your project, then create a local repository.

git init
03

Stage your changes

Stage everything in the current folder, or name individual files for more control.

git add .
04

Save a checkpoint

Write a short, clear message describing what changed.

git commit -m "Add project starter"
05

Connect and publish

Create an empty repository on GitHub, then connect it to your local project.

git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
Remember: Working tree → staging area → commit → remote repository.
03 / Git cheatsheet

Find the command you need.

Popular commands first, then the tools you reach for as your confidence grows.

The everyday essentials

git status

See changed, staged, and untracked files.

git add .

Stage all changes in this folder.

git commit -m "message"

Save staged changes as a checkpoint.

git push

Send local commits to GitHub.

git pull

Fetch and merge remote changes.

git clone <url>

Copy a remote repository to your computer.

git log --oneline

Read a compact commit history.

git diff

Review unstaged changes before committing.

Repositories & remotes

git initCreate a new local repository.
git remote -vList remote URLs.
git remote add origin <url>Add a remote named origin.
git remote set-url origin <url>Change a remote URL.
git fetchDownload remote updates without merging.
git show <commit>Inspect one commit.

Branches & collaboration

git branchList local branches.
git switch -c <name>Create and switch to a branch.
git switch <name>Move to another branch.
git merge <name>Merge a branch into the current branch.
git branch -d <name>Delete a merged local branch.
git push -u origin <name>Publish a new branch.

Undo carefully

git restore <file>Discard unstaged changes in a file.
git restore --staged <file>Unstage a file but keep its edits.
git commit --amendUpdate the latest commit.
git revert <commit>Create a new commit that undoes an earlier one.
git stashTemporarily shelve uncommitted changes.
git stash popRestore the latest stashed changes.

04 / Contribute

Four ways to join an existing project.

Choose the route that matches your access. The goal is the same: make a focused change, explain it clearly, and let the project owner review it.

01

Clone a repository

Best when you have permission to contribute directly or you are studying a project locally.

  1. Copy the repository URL from GitHub.
  2. Run git clone <repository-url>.
  3. Enter the folder: cd <repository-name>.
  4. Create a branch before editing: git switch -c fix/readme.
git clone https://github.com/OWNER/REPO.git
02

Pull, commit, and push

Use this loop when your local copy is connected to the shared repository.

  1. Start from a clean state: git status.
  2. Get the latest shared work: git pull origin main.
  3. Make one focused change and inspect it with git diff.
  4. Stage, commit, and publish: git add . → git commit -m "Describe change" → git push.
pull→edit→commit→push
03

Fork, branch, and open a pull request

Best for public projects where you do not have write access.

  1. Click Fork on GitHub to create your own copy.
  2. Clone your fork locally and add the original as upstream.
  3. Create a feature branch, make your change, then push it to your fork.
  4. Open a Pull Request from your branch to the original project’s main.
git clone https://github.com/YOU/REPO.git
git remote add upstream https://github.com/OWNER/REPO.git
git fetch upstream
04

Download a ZIP

Useful for reading or trying a project without Git history. It is not a contribution workflow.

  1. Click the green Code button on GitHub.
  2. Select Download ZIP and extract it.
  3. Make edits locally, but use Clone or Fork later if you want to send changes back.
Choose Clone or Forkwhen you need commits, branches, pull requests, or a repeatable update path.

05 / Branches

Branches are safe lanes for change.

The main branch should stay reliable. A branch gives your idea its own lane so you can experiment, review, and merge without interrupting everyone else.

mainstable
feature / workshop-pageyour work
↘ merge when ready
01

Create

git switch -c feature-name starts a new branch from your current point.

02

Work

Commit small, meaningful checkpoints. Push the branch so your work is backed up.

03

Review & merge

Open a Pull Request, respond to feedback, then merge when approved.

git switch -c feature/my-change
git push -u origin feature/my-change
git switch main && git pull
